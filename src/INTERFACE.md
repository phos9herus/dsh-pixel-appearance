# Appearance plugin source fragments

`client.js` is generated by `build.mjs` from these fragments, concatenated inside
one `factory(require)` closure. Fragments are plain statements, not modules.

Build order:

1. `00-head.js` — loader wrapper, React bindings, constants, locale dictionaries, shared helpers.
2. `10-engine.js` — pixel field, transition palette, dithering, canvas/preview painter, reactive (event-driven) painter.
3. `20-store.js` — Host-backed config form store and derived state.
4. `30-settings.js` — the `settings.section` React page.
5. `40-runtime.js` — canvas scene mount, theme application, materials, creator launcher, `apply()`.
6. `45-response.js` — Response theme event runtime (pointer halo, composer waves, Agent line waves).
7. `47-review.js` — Review (回顾) theme: content identification, guide building, four exclusive sub-theme animations, and the Review runtime.
8. `99-tail.js` — `return { inject, apply }` and closing wrapper.

All fragments share the factory scope. Do not use `import`/`export`; do not
declare top-level names that another fragment is likely to use without the
`appearance`/`Appearance` prefix unless this document names them.


Theme ids are `native`, `pixel`, `static`, and `response`; the list of theme
cards lives in `30-settings.js` (`appearanceSettingsThemes`) and must match the
`theme` union in the Host `index.js` Config. The `response` theme is the
event-driven pixel theme: it reuses the same palette ramp and Bayer dithering
but paints a pointer halo and expanding waves instead of a looping animation.
Host Config fields used by it: `responseRadius` (CSS px, 40–400),
`haloStyle` (`static` = current halo, `dynamic` = slowly breathing halo),
`trailStrength` (0 = no trail, 1 = longest retention, about 2 s),
`composerWaveMode` (`whole` = wave from the composer card edge,
`caret` = round wave from the text caret), and `waveDamping` (0 = no extra
damping, 1 = fast decay so waves never cross the canvas). The old
`haloTrail` field remains in the Host schema only for stored-config
compatibility and is no longer read. Pixel rendering for
both the Pixel and Response themes uses `pixelSize` (6–32 CSS px), `pixelStyle`
(`square` = current look, `rounded` = every pixel is rounded) and `pixelRadius`
(0–0.5 of the cell size; the settings page shows the equivalent CSS px).
`canvasStyle` (`glass` | `transparent`) is global: it is the main content
surface material for every custom theme (pixel, response, and static), not only
`response`. `composerStyle` / `sidebarStyle` no longer accept `pixel`; both
default to `glass`. Shared helpers: `appearanceStaticImageSource(value)`
resolves a stored value to a safe image source (data URL, http(s) URL, or the
built-in default) and `appearanceCssUrl(value)` builds a quoted `url("…")`.

## Engine API (`10-engine.js`)

```js
/** '#4D6BFE' | '#4d6bfe' | '#4D6BFEAA' → { r, g, b, a } (a = 0..1), or null. */
function appearanceParseColor(value)

/** Relative luminance 0..1 of a CSS hex color; unknown colors → 0. */
function appearanceLuminance(value)

/** True when a custom/hex background wants the dark native color scheme. */
function appearanceWantsDark(hex)

/**
 * Draw one frame into a real canvas at its current device-pixel size.
 * `cell` is optional: pixel-block size in canvas pixels. Omit for an auto grid
 * capped near 4000 cells (settings preview); the live scene passes
 * `pixelSize * devicePixelRatio`. `pixelStyle` is `square` | `rounded`, and
 * `pixelRadius` is a 0–0.5 ratio of the cell (rounded mode only). The field is
 * written to one offscreen layer and scaled with nearest-neighbour sampling; a
 * repeating cell-sized mask clips each pixel for the rounded style.
 */
function appearancePaintPreview(canvas, {
  mainColor, backgroundColor, animation, time, cell,
  pixelStyle, pixelRadius,
})

/**
 * Draw one event-driven frame for the Response theme. `halos` is an array of
 * `{ x, y, radius, strength }` entries (normally the single pointer halo); a
 * single `halo` object is still accepted for compatibility. `trail` stamps
 * persistent main-colour pixels and fades them:
 * `{ x, y, retention, now, active, reset }`, with retention in milliseconds.
 * Each wave is `{ kind: 'circle' | 'rect', radius, width, strength, ... }` with
 * CSS-pixel geometry. Circle waves use `x`/`y`; rectangle waves use a centre
 * `x`/`y` plus `halfW`/`halfH`/`corner`. The same `pixelStyle` / `pixelRadius`
 * options round the response field; `cell` is the CSS pixel size from
 * `pixelSize`.
 */
function appearancePaintReactive(canvas, {
  mainColor, backgroundColor, width, height, dpr, cell,
  pixelStyle, pixelRadius, halos, halo, trail, waves,
})

/** Optional sprite-sheet helper retained for Creator experiments. */
function appearanceBuildSprite({ width, height, mainColor, backgroundColor, animation })
```

The engine builds a six-level colour ramp from background to main: the two end
colours plus four automatically interpolated transition colours. Coverage is
quantised to a ramp level with Bayer 8×8 ordered dithering, so pixel blocks can
be background, main, or an intermediate colour. All time terms are integer
harmonics of `theta = 2*pi*frac(time / 8)` for a seamless loop. Coverage at 0
stays exactly at the background level, so empty areas contain no fixed dots.

## Settings page (`30-settings.js`)

```js
function AppearanceSettingsPage({ t, store, startCreator, close })
```

- `store.getSnapshot()` returns `{ config, revision, error }`.
- `appearanceUseStore(store)` subscribes and re-renders.
- `store.set(patch)` writes a partial config object to the Host-backed settings namespace.
- `startCreator('theme' | 'animation')` opens Creator; `close()` closes Settings.
- Theme cards are built from `appearanceSettingsThemes`; selecting `static`
  reveals the static-picture section below the theme section. That section
  reads `staticImage` / `staticBlur` / `staticDim`, offers a local file picker
  (`appearanceSettingsReadImage` + `appearanceSettingsShrinkImage`, max 1920 px,
  JPEG 82%) and an image URL field, and shows the picture with blur + dim in
  the preview.
- **Canvas style** (`canvasStyle`: `glass` | `transparent`) is shown for every
  theme and disabled only under Native. It controls the `[data-slot="main"]`
  surface for all custom themes: `glass` paints a translucent tint plus a
  `backdrop-filter` layer over the pixel animation or static picture;
  `transparent` removes that layer.
- **Pixels** (`pixelSize` 6–32 px, `pixelStyle` `square` | `rounded`,
  `pixelRadius` 0–0.5) is enabled for the Pixel and Response themes and
  disabled under Native / Static. The corner-radius slider displays the
  equivalent CSS px (`pixelRadius * pixelSize`) so it visibly adapts when the
  pixel size changes.
- Selecting `response` reveals extra sections: **Response effect**
  (`responseRadius`, 40–400 px, `haloStyle` `static` | `dynamic`, and
  `trailStrength` 0–1 shown as 0–100%), **Composer wave** (`composerWaveMode`:
  `whole` | `caret`), and **Wave damping** (`waveDamping`, 0–1, shown as
  0–100%). The live preview (`AppearanceSettingsResponsePreview`) reuses
  `appearancePaintReactive` with a moving demo halo, one circle wave, and one
  composer wave whose origin follows `composerWaveMode`;
  `appearanceResponseHaloPulse` drives the breathing demo and the demo passes a
  `trail` object using `appearanceResponseTrailRetention` so the temporal trail
  also previews; `appearanceResponseWaveReach` / `appearanceResponseWaveAmp`
  keep its damping identical to the runtime.
- `appearanceEffective(config, scheme)` resolves colours, composer/sidebar fills,
  material blur, `responseRadius`, `haloStyle`, `trailStrength`, `canvasStyle`,
  `pixelSize`, `pixelStyle`, `pixelRadius`, and the static values `staticImage`,
  `staticBlur`, `staticDim`; for the static theme it also supplies a fallback
  sidebar glass fill when the sidebar material is `native`.
- The page owns its `<style>` tag and uses `apx-` class names plus DSH theme tokens.

## Runtime (`40-runtime.js` and `45-response.js`)

`appearanceMountScenes` inserts two layers per app frame
(`[data-slot="root"] > div`). Both sit at `z-index:0` while the
sidebar/center/rightbar columns and bottom row move to `z-index:1`, and the
scene gets `data-appearance-scene` whenever a custom theme is active. All three
custom themes apply the global `canvasStyle` to `[data-slot="main"]`: `glass`
adds a translucent tint plus `backdrop-filter` through a `::before` layer over
the canvas or static picture, `transparent` leaves the surface clear. The Pixel
and Response painters both receive `pixelSize`, `pixelStyle`, and `pixelRadius`;
they write the field to one offscreen layer, scale it with nearest-neighbour
sampling, and (for `rounded`) clip it with a repeating cell-sized mask.

- Pixel theme: a `<canvas class="appearance-pixel-canvas">` painted by
  `appearancePaintPreview`; the center/right columns and bottom row are made
  transparent, while the sidebar column keeps its configured fill so
  glass/transparent materials reveal the canvas. The loop pauses when the tab
  is hidden or `prefers-reduced-motion` is set. This adapts the presentation
  style used by `dsh-ascii-whales`.
- Response theme: the same canvas, painted by `appearancePaintReactive` through
  `45-response.js`. A pointer halo follows the pointer; `pointerdown` spawns a
  circle wave; typing or deleting in the composer, caret movement
  (`selectionchange`/`pointerup`; keyboard caret keys are left to
  `selectionchange` in caret mode), and new assistant rows or streamed markdown
  lines in `[data-chat-flow]` spawn waves. Whole mode uses the composer card
  edge as a rounded-rectangle wave origin; caret mode uses the collapsed DOM
  Selection rect and falls back to the card edge when no caret rect is
  available. `waveDamping` shrinks each wave's reach to `maxEdge * (1 - 0.8d)`
  and decays its amplitude with distance; `waveDamping = 0` keeps the original
  flat amplitude and 120 px edge fade. `haloStyle` `dynamic` calls
  `appearanceResponseHaloPulse` to oscillate the halo radius by ±12% and its
  brightness by ±10% over a 2.6 s cycle; `static` keeps scale/strength at 1.
  `trailStrength > 0` maps to a retention time of 250–2000 ms
  (`appearanceResponseTrailRetention`). Every paint stamps the grid cell under
  the pointer (plus interpolated cells along the movement segment) with
  `now`; `appearancePaintReactive` keeps a per-cell birth-time buffer and uses
  `fade = 1 - age / retention` as coverage, so stamped pixels begin as the
  main colour and gradually dither back to the background. The trail fades
  after the pointer leaves; `trailStrength = 0` disables it and clears the
  buffer. Both static and dynamic halo styles can have a trail.
  `prefers-reduced-motion` forces the static halo and disables the trail while
  the continuous loop is paused.
- Static theme: a `<div class="appearance-static-layer">` with a
  child `.appearance-static-image` that uses `background-image`,
  `background-size:cover` and `background-position:center`, so the picture
  keeps its aspect ratio; an 80 px overscan behind `filter:blur()` prevents
  transparent blur edges. The layer spans the whole frame below the title bar
  (`--dsh-frame-top-clearance`), so expanding the right sidebar never stretches
  it, and a `::after` overlay applies `staticDim`. The sidebar always gets a
  translucent glass fill (falling back to one even for the Native material) so
  the picture also shows under the sidebar. Layer CSS variables
  (`--apx-static-image`, `--apx-static-blur`, `--apx-static-dim`) are written by
  `applyStaticLayer` only when the source/blur/dim tuple changes.

The composer material uses the stable `[data-composer-card]` attribute:
`isolation:isolate`, transparent background and
`--dsw-specific-input-major:transparent`, with the frosted layer on
`[data-composer-card]::before` (`backdrop-filter` plus alpha fill). The Pixel
material option — and its `::after` pixel outline — has been removed; composer
and sidebar styles are now `native` / `glass` / `transparent` only. Sidebar
material is applied to the whole column (`background-color` +
`backdrop-filter`) while the sidebar root stays transparent.

## Review theme (`47-review.js`)

Theme id `review` (ui: 回顾 / Retrospective). It is a pixel-canvas theme like
Pixel and Response and shares their token overrides, `canvasStyle`, composer
and sidebar materials, and pixel settings. Its animation is **not** a looping
item of `APPEARANCE_ANIMATIONS`: it is driven by conversation content through
four sub-theme animations exclusive to this theme.

Shared constants (declared in `00-head.js`):

```js
const APPEARANCE_REVIEW_SUBTHEMES = ['code', 'investigate', 'create', 'discuss']
const APPEARANCE_REVIEW_CHOICES = ['auto'].concat(APPEARANCE_REVIEW_SUBTHEMES)
```

Host Config fields added for this theme: `theme` accepts `review`, and
`reviewSubTheme` is `auto | code | investigate | create | discuss`
(default `auto`). `auto` follows content; any other value locks that
sub-theme while still deriving the animation seed/energy from content.
`appearanceSettingsHostFields` must list `reviewSubTheme` so a stale Host
shows the restart notice. Selecting the theme adds a Review card to the theme
list and reveals the **Sub-theme animation** section only under `review`.

### Content identification (design)

A guide is derived from the conversation, never from model output:

- **Active session**: read the rendered Chat flow
  (`[data-conversation-content] [data-chat-anchor-key]` rows, capped to the
  latest ~100). Use `data-chat-flow-kind` (`user`, `assistant-step`,
  `tool-call`), `querySelectorAll('pre, code')` counts, question marks, and a
  weighted keyword table (Chinese + English) to score the four sub-themes.
  Structural signals: code blocks / file paths / code-ish tool calls → Code;
  search / read / grep / web tools and question density → Investigation;
  write / design / create / deliverable words and `write`/`edit` tools →
  Creation; conversational markers, many turns, few tools, short turns →
  Discussion.
- **New session screen** (Chat flow has no rows, or the current Session row is
  `blank`): pick the most recent non-blank Session from
  `ctx.get('sessions').list` (sorted by `updatedAt`, excluding the current
  Session), retain it read-only through
  `ctx.sessions.retain(id, { source: 'gateway' })`, wait for `reference.ready`
  with a short timeout, scan the latest `binding.eventSource` entries for
  strings / event types (`tool`, `assistant`, `user`), then release the
  reference immediately. If the read fails or times out, fall back to the
  Session title and metadata. Never switch the UI to that Session.
- Scores use a margin + hysteresis rule so the sub-theme does not flicker on
  every mutation: a new kind only wins when its score clearly exceeds the
  current one; ties prefer the previous kind, then Discussion (empty content
  also starts with Discussion). Running the session updates the guide on
  debounced Chat mutations / turn completion; a `manual lock` overrides the
  detected kind.

The detector exposes a stable guide object (plain JSON, no DOM references):

```js
{
  kind: 'code' | 'investigate' | 'create' | 'discuss',
  source: 'current' | 'recent',
  title: string,            // guiding session title (may be '')
  seed: uint32,             // hash of sampled content, stable per sample
  energy: 0..1,             // volume / activity
  density: 0..1,            // tool & code density
  progress: 0..1,           // replay position (0 for a new session)
  at: epoch ms,
}
```

### Painter API

```js
/**
 * Paint one Review frame. `animation` is one sub-theme id. `guide` is the
 * object above (a neutral guide is used when it is missing). Every animation
 * is a seamless 8 s loop: every time term is an integer harmonic of
 * theta = 2π·frac(time / 8), and guide-derived phases stay constant per
 * sample. Reuses the palette ramp, Bayer 8×8 dithering, pixelStyle /
 * pixelRadius and one offscreen pixel layer, exactly like the other painters.
 */
function appearancePaintReview(canvas, {
  mainColor, backgroundColor, animation, guide, time, cell,
  pixelStyle, pixelRadius,
})
```

The four sub-theme animations:

- `code` — horizontal code lines scroll upward through a replay position;
  each line has seed-derived length/indent, token gaps, and indent guide bars;
  a cursor block and a scanning highlight follow `progress`.
- `investigate` — a radar beam sweeps from a seed-derived centre, expanding
  rings travel outward, and seed-scattered evidence pixels light up as the
  beam crosses them and then fade.
- `create` — an artistic fountain pen (split nib, grip section, cap band,
  pocket clip and finial) writes a poem from left to right, completing one
  horizontal line at a time. Seed-derived character strokes appear behind the
  nib, a wet ink bead pools under the tip, and the pen lifts and travels to the
  next line; after the last line the page and pen fade out before the loop
  restarts.
- `discuss` — two wave trains enter from the left and right edges and
  interfere in the middle, with alternating left/right speech pulses and
  travelling turn dots.

`40-runtime.js` adds `review` to the theme mode switch, mounts the same
`.appearance-pixel-canvas` layer, starts/stops the Review runtime with the
other event runtimes, forwards MutationObserver records to
`onMutations(records)`, and paints through `appearancePaintReview` with
`time = now / 1000`. The continuous loop pauses for
`prefers-reduced-motion` / hidden tabs like the other pixel themes, so under
reduced motion only one static frame is painted.
`appearanceStartCreator` accepts kind `review` and uses
`t('creatorPromptReview')`. `30-settings.js` renders the sub-theme cards from
`APPEARANCE_REVIEW_CHOICES` (auto + four), the current guide status, and an
`AppearanceSettingsReviewPreview` canvas that calls `appearancePaintReview`
with a demo guide. Selecting a card writes `reviewSubTheme`.
